# Moon bots 1.0

Build request: replace Winston with Io (level 10 tempo), Callisto (level 7–9 combo), Europa (level 7–9 aggro), and Ganymede (very weak). All start at version `1.0`. They continuously play the existing AI or each other and feed the stats website separately from human games. The operator approved Codex implementation and the four profiles proposed in chat: fixed level 8 for Callisto/Europa, level 1 for Ganymede; Callisto still takes wins. No production deployment, account creation, human matchmaking, dependency updates, or training service is selected.

Named bot identities are simulation participants, not real login accounts.
- `catalog/src/server.mjs:78` serves bounded public proxies. Add the bot route with validation/projection and the existing size/timeout/no-redirect conventions. The stats frontend itself is outside this checkout; provide a developer contract and example for its consumer.

Use one shared JSON roster (`data/bot_profiles.json`) for names, versions, levels, and styles, consumed by Godot and Node. Bot release versions are strings independent of the rules and normal AI policy versions. Historical snapshots must not be relabeled by a later roster change.

## Behavior and acceptance

1. Io/Callisto/Europa have materially different deck preferences and state evaluators. Focused board/action scenarios demonstrate tempo, combo synergy/retention, and face pressure differences. Default opponent policy retains current evaluation and behavior. Ganymede's independent random policy demonstrates mistakes without illegal actions.
2. A headless CLI plays a full match using canonical GameState/HeadlessTurn, snapshots both identities, versions, levels, starting decks, first player, rules version, seed, winner and turns. A completed draw may be stored separately and counted honestly; action/turn/wall-clock limits abort the attempt without counting it as a result. No graphics, account secrets, or normal user-save reads/writes are required; the worker redirects user storage to task-owned paths.
3. A single-process Node worker continuously cycles all six named-bot pairs and four bot-versus-standard-AI pairs, swapping first player and rotating factions between rounds. `--matches=N` provides a bounded run; the default continues until stopped. It runs one game at a time, bounds child duration, cleans the child on stop, and backs off after failed games rather than spinning. Persistent cursor advances only after successful durable insert; restart safely retries the same pending result. Duplicate insertion cannot add another result. Document single-worker operation.
4. Results are validated before durable insertion: known roster IDs and corresponding metadata, legal deck sizes/copy limits/faction membership/non-tokens, valid first/winner/turn/rules/seed fields. Bot drafting passes the public catalog's collectible/non-token allowlist into the existing builder before selection; ordinary AI generation and publication selection remain unchanged. Reject entire results/decks with unpublished IDs at insertion and projection, never publish partial compositions. No HTTP ingest endpoint or client-controlled provenance flag is introduced. Writer uses the database connection already configured for the service; it never touches players, rewards or ranked settlements.
5. The public bot route returns only aggregate data: simulation label, generated time, applied time window, bot/version/level identities, physical games, wins/losses/draws, exact deck compositions and opponent-specific records. Snapshot both `RulesVersion.RULES_VERSION` and `AIController.POLICY_VERSION` as rulesVersion/engineVersion; all public bot/deck/matchup keys include both dimensions as well as bot ID/version/level. Different rules, baseline policies, styles or releases using the same deck are not merged or relabeled from the current roster. Reversed perspectives are counted once per seat; mirrors and draws remain internally consistent. Human/tester counts and private match IDs/seeds/account data are not exposed. Query accepts `days` 1..365 (default 30), rejects unknown/repeated/malformed values with 400. Bot versions remain explicit in rows rather than filtering away other opponents' releases.
6. Relay and catalog support GET/HEAD/OPTIONS and anonymous CORS; other methods return 405. Successful aggregates cache 60 seconds/coalesce reads. Missing bot table (before rollout) returns honest empty data; database/upstream errors or bounds exceeded return generic 503 rather than stale/truncated success. Bound source at 50,000 physical matches and response at 4 MiB. Existing human card/deck stats remain unchanged and exclude all bot games by construction.
