## Grounded behavior and shape

`scripts/game/ranked_bots_client.gd` currently always queues after drafting and completion (`_queue`, `_finished`). Its filtered planning state and existing profile policies own named-bot decisions. Normal ranked fallback uses `RankedProgress.get_ai_level` (`ranked_progress.gd:82`): Orbital 3, Lunar 4, Planetary 5, Solar 6, Nebular 7, Galactic 8, Cosmic 9, all Legend 10. `main.gd:2563` builds a random-faction archetype opponent. `HeadlessTurn` executes real commands without UI; `GameState.to_net_dict` provides filtered views and records card plays. Reuse these owners for headless local ranked-AI games, keeping ordinary named-bot decisions and archetype drafting. An AI match is local/client-reported, never relabeled server-verified PvP.

Extend the existing four-socket worker, rather than provisioning extra AI accounts or introducing a second worker. Each bot alternates independently, starts with AI when there is no completed history, and derives the next mode from its most recent persisted settlement on reconnect/restart. Resume active server matches before starting AI. Finished AI games award the normal AI ladder result once, with no hidden Elo change; normal queued games retain ordinary matchmaking, settlements and rewards. Do not fabricate a result on a cap, invalid command, crash or disconnect. Maintain existing action pacing. Bound local attempts by time/turn/action limits; stop/retry failed attempts without counting them as wins, draws or completed alternation steps.

Add a bot-only authenticated AI-start handshake to the existing relay protocol. Read the trusted owned mapping and current rank, choose AI difficulty server-side, refuse an active/pairing match or another live AI seat, and remove queue membership before admission. Bind the in-memory admission (match ID and difficulty) only to the current verified open socket; use the existing ticket ordering/close cleanup. A reconnect can re-admit an unfinished local game with the same identity; an acknowledged result is replayed idempotently after lost acknowledgments. No durable AI lease/recovery service. The existing worker advisory lock still owns single-supervisor execution.

Human clients persist unacknowledged reports and retry them after a relay restart (`auth.gd:116–211`); deleting settlements alone would award an old report twice. Add only an internal `ranked_result_tombstones` table keyed by match/player, with the normal player foreign key, for reset anti-replay protection. During reset, copy existing settlement keys into it transactionally before deleting payloads/history; retain older tombstones on later resets. No outcomes, decks, plays or statistics are retained there or exposed publicly. Before accepting a new legacy/AI result, an existing tombstone returns a successful replay acknowledgment containing current account rank, without awards or new match/statistics rows, so existing client outboxes clear safely. This preserves the existing no-double-award contract without client-clock cutoffs, new Web exports or retained historical report payloads. Never tombstone an unrecorded report merely because it was pending on a client.

Extend existing AI result recording for owned bot accounts: require matching admission/difficulty/current rules and AI version for a new result, stamp immutable bot profile from the database rather than client flags, and apply the result under a locked player row using existing ladder/settlement owners. Ordinary human reports and canonical PvP remain compatible. Never queue a bot while its AI admission is live. Completed/failed admissions clear on the matching lifecycle; stale frames cannot clear a newer admission. The worker retains a completed unacknowledged report across socket reconnects and retries the same match ID, not a new game.

Shared card/deck statistics include these genuine ranked AI games. Bot accounts never become human testers; human-only filtered cohorts retain their exclusions. The dedicated ranked-bot API includes these records against a public Standard AI participant at the actual rank-derived level, with separate version/level keys. Its methodology is mixed when local AI reports are included; existing pure-PvP/simulation responses remain accepted. Preserve bounded counts, publication filtering and public projections; no account IDs, tokens, seeds or match IDs become public. Status adds a public `playing_ai` activity labeled Playing ranked AI, with the four identities and current visible ranks unchanged.
