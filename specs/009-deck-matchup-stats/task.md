## Public contract

`GET /data/stats/deck-matchups.json?mode=ranked_ai&days=30&rulesVersion=latest&aiVersion=latest&aiLevel=10`

- `mode` is `ranked_ai` (default) or `authoritative_pvp`; never pool them. `days` is integer 1..365, default 30. Rules version is a positive integer, `unknown`, or `latest` (default). AI mode additionally supports AI version as positive integer/unknown/latest and level 1..10 (default 10). Reject unknown, repeated, malformed or irrelevant parameters with 400. Return the resolved filters and available version/difficulty values so a frontend can make valid selections.
- Resolve cohorts deterministically: begin with valid mode/time-window records, apply AI level and all explicit version selections, resolve `rulesVersion=latest` first, then `aiVersion=latest` within that resolved rules cohort. Each latest selection is the highest known remaining version, or `unknown` if no known version remains. This prevents independent maxima from inventing an empty combination. `availableFilters.rulesVersions` is conditioned on mode/time/level and any explicit AI version; `aiVersions` is conditioned on mode/time/level and resolved rules version, ignoring the requested AI version; `aiLevels` lists the mode/time window's valid levels as discovery metadata (not a promise every version/level combination exists). It must not mix versions. Missing AI policy version is always a separate unknown cohort; never infer the old policy from difficulty. Empty cohorts return empty arrays and zero games, not fabricated rates. Explicitly selected nonexistent versions are valid empty cohorts.
- A deck ID is SHA-256 of JSON for sorted `[cardId, copyCount]` pairs. Input order does not matter; counts do. Publish `cards: [{id,copies}]` in that same order and `factions` from the published catalog. Reuse actual game deck bounds/copy limits. Reject the whole match from this API if either composition is malformed, contains a token or an unpublished ID. Never project a partial deck and call it exact.
- Envelope: `generatedAt`, `filters`, `availableFilters`, `methodology`, `games`, `decks`, `matchups`. `games` counts physical eligible matches. Each deck row contains `id`, `cards`, `factions`, `role`, plus statistics. Each matchup row contains `deckId`, `opponentDeckId`, `role`, `opponentRole`, plus statistics. Roles are `human`/`ai`; PvP has two human perspectives. Never merge human and AI performance for the same composition.
- Statistics: integer `matches`, `wins`, `losses`; fraction `winRate`; `winRateInterval: {lower,upper}` using Wilson 95%; integer `testers`; `averageTurns` or null and `turnSamples`; `first`, `second`, `unknownFirst` each with matches/wins/losses/winRate (null at zero). A sample is a seat-game. Mirrors therefore contribute both seat results to the same human/PvP bucket, while human-v-AI mirrors remain separate by role. Distinct testers means real human participants involved in those samples, not independent observations or AI accounts. Public output contains only counts, never their identifiers.
- Include both AI perspectives with reversed outcomes and distinct role keys. Do not create another settlement or reward. Old AI rows without first-player metadata contribute to unknownFirst; old PvP facts without turns contribute no turn sample. Do not synthesize historical mulligans, draw/play facts, first-player fields or AI versions.
- Samples start at one; label as preliminary. State that repeated testers make intervals descriptive rather than proof of independent samples or causal balance. Public exact deck compositions and small-sample aggregates can permit inference; do not claim anonymization prevents that.

## Implementation shape and failure behavior

Use the existing live aggregate owners, adding a focused relay module and a catalog fetch/strict public-field projector. Existing JSON columns suffice; no migration is needed. Read source rows with parameterized time/mode filters and query timeout, with a hard 50,000-match ceiling. Fail generically with 503 rather than silently truncating when input/output bounds are exceeded. Limit response to 4 MiB. Cache successful snapshots for 60 seconds, coalesce concurrent identical requests, bound cache keys to 64, and never cache an error or serve stale success after a failed refresh. The catalog bounds upstream time/bytes, refuses redirects and validates/projects the public shape, counts, role relationships and catalog IDs; drop unknown extra upstream fields rather than forwarding private data. No caller-controlled upstream URL.

GET/HEAD/OPTIONS with anonymous CORS; unsupported methods 405. Missing authoritative tables produce an honest empty PvP result while AI remains usable. Database or upstream failures are 503, never empty success. Static routes, health check and websocket upgrades remain independent. Document normal deployment order: relay then catalog; until relay supports the route the catalog returns 503. A new client build is needed only for future AI version/first-player metadata; saved deck/result rows already support historical deck matchup records in their unknown cohort.

Update `catalog/README.md`, replace the obsolete website brief with the current developer-facing contract and examples, and update owning game/server docs only for changed claims. Export the Godot Web client with new metadata, preserving unrelated importer defaults and unowned files. No game rules change, so do not increment the card/rules version for telemetry alone.
